# Agent Instructions for pyapi Repository

This document provides guidance for agents working within this repository to ensure efficient and accurate task completion.

## Core Development Commands

- **Running the application:** The primary entry point for the FastAPI application is `app/main.py`.
  ```bash
  uvicorn app.main:app --reload
  ```

- **Database Migrations (Alembic):**
  - Create a new migration: `alembic revision -m "description"`
  - Apply latest migrations: `alembic upgrade head`
  - View migration history: `alembic history`

## Key Directories

- **`app/`**: Main application source code.
  - **`app/core/`**: Central infrastructure.
    - `config.py`: Configuration management (loads environment variables).
    - `database.py`: SQLAlchemy engine and session setup.
    - `seeder.py`: Core logic for database seeding.
  - **`app/modules/`**: Feature-specific domain logic. Each module (e.g., `auth`, `users`, `chatbots`, `roles`) typically follows a consistent pattern:
    - `router.py`: FastAPI endpoints.
    - `service.py`: Business logic and service layer.
    - `models.py`: SQLAlchemy database models.
    - `schemas.py`: Pydantic models for validation and serialization.
  - **`app/shared/`**: Common utilities and dependency injection helpers.
- **`alembic/`**: Database migration configuration.
  - `versions/`: Versioned migration scripts generated by Alembic.
  - `env.py`: Migration execution environment setup.

## Development Conventions

- **Frameworks:**
  - **FastAPI**: Used for the web API layer.
  - **SQLAlchemy**: Used for ORM operations.
  - **Alembic**: Required for all database schema changes.
- **Environment Management:** Dependencies are defined in `requirements.txt`. Ensure your environment has these installed before running tests or the application.
- **Seeding:** The application includes a seeder mechanism (`app/seeds.py` and `app/core/seeder.py`) for initializing database data.

## Verification

- **Lint/Type-Check:** The project does not currently have explicit config files for this, but follow standard Python type hinting (PEP 484) and naming conventions.
- **Testing:** If adding new features, create corresponding tests in the `tests/` directory (if it exists) or within the relevant module. Run them using `pytest`.
